# ADR-008: 附加服务（MySQL / Redis）随 catalog 按需分发，daemon 统一托管

## Status: Accepted (2026-10-26 · 用户需求变更 R13)

## Background
用户（2026-10-26）明确要求增加 MySQL 与 Redis。原 Spec §3 将「数据库服务」列为不做（估 5 人月全量），但该估算针对的是"多引擎 + 全功能管理"的重形态；Laravel 开发的最小刚需是：MySQL 起停 + 端口/数据目录 + Redis 起停 + 与 PHP 扩展闭环。形态收窄后工作量可控，且与 PHP 分发体系完全同构（catalog + SHA256 + 按需下载 + supervisor 托管），复用度极高。

## Decision
1. **分发同构**：MySQL / Redis 走与 PHP 相同的 catalog 通道（版本 + SHA256 + URL，与 app 更新解耦），下载到应用数据目录，禁随包。
2. **版本策略**：MySQL 首发 8.4 LTS（8.0 备选第二批）；Redis 首发 7.x 单版本（版本管理 v1.x 再议）。
3. **平台二进制来源**：
   - MySQL：官方社区版二进制（macOS tar.gz / Windows zip），直接可用。
   - Redis：macOS 官方无预编译——CI 自编译 prebuild（与 node-pty 同纪律：随分发体系、可执行位校验）或检测到 Homebrew 已装则复用并提示；Windows 用社区维护预编译 zip（7.x）。
4. **进程托管**：daemon supervisor 服务族扩展（与 php/nginx 同机制：健康检查、看护、按需启动）；默认**不登录自启**（与 nginx 常驻不同——数据库按需起，省资源）；Windows 不注册系统服务（自写看护，同 nginx 纪律）。
5. **端口与冲突**：MySQL 3306 / Redis 6379；占用 → PORT_CONFLICT（复用现有错误码）+ 进程名/PID/释放指引（同 80/443 机制）。
6. **数据目录**：`<appdata>/mysql/data`（`mysqld --initialize-insecure` 初始化）；root 空密码 + 仅监听 127.0.0.1（本地开发工具惯例，Herd 同款）；README 与 `corral doctor` 明文风险边界（禁生产用途）。
7. **CLI 命令族**（语法终裁延续冒号风格）：`corral mysql:start|stop|restart|status`、`corral mysql:install <v>|uninstall <v>`、`corral redis:start|stop|restart|status`；全部支持 `--json`。
8. **env 引导闭环**：`corral doctor` 与站点 link 成功输出里，DB_HOST/DB_PORT/DB_DATABASE/DB_USERNAME/DB_PASSWORD 与 REDIS_HOST/REDIS_PORT 建议值随服务运行状态动态给出（服务未起时提示 `corral mysql:start`）。

## Consequences
- 正面：Laravel 开箱即用闭环（PHP + nginx + TLS + MySQL + Redis 全在工具内）；差异化直击 Herd 付费墙（附加服务免费）。
- 负面：包体分发 catalog 增大（MySQL ~150MB 按需）；macOS Redis 自编译 CI 成本；MySQL 数据目录损坏/大库场景的容错（doctor 加 data 目录完整性探测）；MVP 排期 +2~3 周（12 → 14-16 周）。
- 风险备案：MySQL 官方 tar.gz 无代码签名——SHA256 + 官方域名 HTTPS 双校验是唯一防线（写入 Spec 安全红线）。
