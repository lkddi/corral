# ADR-001: 使用 Electron + TypeScript 作为应用外壳与核心运行时

## Status: Accepted (2026-10-26)

## Background
一人 TS/JS 开发者，需双端桌面应用 + 常驻服务编排 + CLI；交付速度是首要约束。本产品 90% 工作量是进程编排、配置生成、特权操作——Node.js child_process / fs / net 的主场。

## Decision
Electron（electron-vite + electron-builder 构建）+ Node 核心。CLI/GUI/daemon 同一语言同一代码库；npm 生态直接复用（mkcert 壳调用、NSSM 随包等）。版本锚定以 npm registry 实测为准（2026-10-26 复核：electron 45.0.0 / React 19.3.1 / Tailwind 4.3.3）。

## Amendment (2026-10-26 补充决议)
CLI 运行时 = 随包独立 Node **24.22.0** + esbuild 零依赖编译 JS，**不复用 Electron 二进制**（ELECTRON_RUN_AS_NODE 冷启动达不到 <300ms 红线）。Node 小版本与 Electron 45 捆绑的 Node 24.22.0 逐位对齐（npm 24.x 已有 24.22.1，升级走 ADR-lite、不自动跟随）——全系统（GUI main / daemon / CLI / helper）同一个 Node 小版本、同一个安全补丁节奏、一个 ABI 故事。CLI shim / daemon / Windows helper 三处共用同一运行时；CLI 硬规则：零运行时依赖、不引 commander/yargs、懒连接、即用即退。降级路径：Node SEA（实验特性，产物约 145MB）→ Go 薄客户端（最后手段）。包体代价：安装包约 150-200MB。

## Consequences
- 正面：交付速度最大化，核心逻辑 100% 自主可拥有；双平台渲染一致；自动更新与签名公证工具链最成熟。
- 负面：安装包 80-150MB、空闲内存 150-300MB，会被社区与 Herd（原生）对比；需以「常驻托盘 + 按需建窗 + 核心轻量」控制观感。
