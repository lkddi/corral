# node-pty 双端 Spike 报告（R10 早期验证项）

> 日期：2026-10-26 | 执行：大湾区靓仔（总监，一手复验）+ mvp-dev-expert-team-architect（初版被打回，见文末打回记录）
> 目的：验证「node-pty 宿主 = daemon（纯 Node 24.22.0，不进 Electron main）」的可行性与打包影响，为 Spec §11 已知坑提供实证
> Scratch：/tmp/corral-pty-spike（Node 24.22.0 官方 tarball + node-pty 安装实物保留，可复现）

## 1. 环境矩阵

| 项 | 值 | 证据 |
|---|---|---|
| Node 运行时 | **v24.22.0**（darwin-arm64，官方 tarball 解于 scratch） | `node --version` |
| Node ABI | **137**（modules） | smoke [env] 行：`modulesABI=137` |
| node-pty 版本 | **1.1.0**（`^1.1.0` 解析结果；npm 最新 stable 即 1.1.0，之上只有 1.2.0-beta 系列；**1.1.20 不存在**） | package-lock.json：`node-pty-1.1.0.tgz` |
| 平台 | darwin arm64（本机实测）；Windows 侧为实物查证（见 §4） | — |

## 2. Prebuild 覆盖（一手 find/ls 实证）

`node_modules/node-pty/prebuilds/` **四平台齐全**：

| 平台 | 产物 | 结论 |
|---|---|---|
| darwin-arm64 | pty.node + spawn-helper | 命中即用（见 §3 可执行位坑） |
| darwin-x64 | pty.node + spawn-helper | 同上 |
| win32-arm64 | pty.node + conpty.node + conpty.dll + OpenConsole.exe + winpty.dll + winpty-agent.exe 全家 | 预编译二进制在位 |
| win32-x64 | 同上全家 | 预编译二进制在位 |

**结论：node-pty 1.1.0 四平台全 prebuild——Windows 无需源码编译、无 VS2022/Win SDK 工具链门槛**（初版报告「Windows prebuild 缺失、必须源码编译」不实，已作废）。daemon 分发按平台各带 prebuilds/ 下对应产物；禁 electron-rebuild（daemon 不跑在 Electron 里，原生模块与 Electron main 的 ABI 无关）。

## 3. 冒烟结果（一手复跑，含真坑）

**首次裸跑失败**：`SMOKE FAIL: posix_spawnp failed`

**根因（一手定位）**：npm 解包丢失 `prebuilds/darwin-arm64/spawn-helper` 可执行位（解包后为 `-rw-r--r--`）。node-pty 的 macOS spawn 链路依赖该 helper，丢失即 posix_spawnp 失败。

**修复后复跑（chmod +x spawn-helper）全过**：

```
[A] exitCode=0 signal=0 output="pty-ok"
[A] PASS
[B] resize(120,40) no-throw OK
[B] post-kill exitCode=0 signal=1 echo="hello-pty\r\nhello-pty"
[B] PASS
[env] node=v24.22.0 modulesABI=137 platform=darwin arch=arm64
SMOKE DONE
```

- A：`spawn('/bin/sh', ['-c','echo pty-ok; exit 0'])` → onData 读到输出 + onExit 码 0 ✓
- B：`spawn('/bin/cat')` → write 回显、resize(120,40) 无异常、kill 后 onExit(signal=1) ✓

**这是本 spike 最有价值的发现**：见 §5 坑位 #1。

## 4. 冷启动开销（一手复测，chmod 后，10 次）

| 指标 | 值 |
|---|---|
| median | **20.0ms** |
| p95 | **90.4ms** |
| min / max | 15.2ms / 90.4ms |

口径：独立 Node 进程内 `require('node-pty') + pty.spawn('/bin/sh', ['-c','true'])` 到 onExit 的端到端耗时（process.hrtime.bigint 计）。对照 CLI 冷启动 <250ms 预算（I1 出口条件）：median 占 8%、p95 占 36%——**余量充足**；注意口径为 spike 进程，非最终 CLI 产物（CLI 还含 esbuild 产物加载 + daemon 连接）。**CLI 不得 require node-pty/ws**（Console 宿主在 daemon）。

## 5. Windows 侧（实物查证，本机无法实测运行）

- prebuild 覆盖 win32-x64/win32-arm64（§2 已列实物）——**安装链路与 mac 对称，无需 VS 工具链**
- Windows pty 后端 = ConPTY（win32-x64 prebuild 含 conpty.node + OpenConsole.exe 全家），Node 24 下 API 面与 posix 一致（spawn/write/resize/kill/onData/onExit）
- **待 CI 实证项**（Spec 验收）：Windows runner 上 npm install 后 spawn 冒烟 + **spawn-helper 可执行位坑在 Windows 的对应面**（winpty-agent.exe / OpenConsole.exe 的可执行位是否同样在解包中丢失——npm 对 .exe 的处理与 unix helper 不同，需 CI 验证；若同样丢失，postinstall 逻辑双端统一）
- ABI 依赖场景收窄为：**Node major 升级（24→26）时 prebuild 失效需重编或等上游**；minor 升级（24.22.0→24.x，ABI 137 不变）prebuild 复用

## 6. 给 Spec §11 的建议条目（已由总监核准并入 Spec）

1. node-pty 1.1.0 四平台全 prebuild，无需源码编译/无 VS 门槛；daemon 按平台分发 prebuilds/ 产物，禁 electron-rebuild
2. **npm 解包丢 spawn-helper 可执行位 → 裸装后 spawn 报 `posix_spawnp failed`；安装/postinstall 必须 chmod +x（darwin）或 CI 校验**；Windows 侧 .exe 可执行位待 CI 实证
3. node-pty ABI 绑 Node major；minor 升级 prebuild 复用，major 升级需重编（ADR-lite）
4. CLI 禁 require node-pty/ws（宿主在 daemon；CLI 冷启动预算约束）

## 7. 复现命令

```bash
cd /tmp/corral-pty-spike
./node-v24.22.0-darwin-arm64/bin/node smoke.js        # 裸跑：posix_spawnp failed

./node-v24.22.0-darwin-arm64/bin/node smoke.js        # A/B 全过
./node-v24.22.0-darwin-arm64/bin/node coldstart.js    # median 20.0 / p95 90.4
```
